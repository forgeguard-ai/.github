# Contributing

Thanks for your interest. This is the default guide for ForgeGuard AI repositories; a
repository's own `CONTRIBUTING.md` takes precedence and usually says how to run its checks.

- **Start with an issue** for anything beyond a small fix, so we can agree on the approach
  before you invest time in it.
- **Keep pull requests focused:** one change, with tests or a clear way to verify it, and
  documentation updated in the same pull request when behavior changes.
- **Maintained forks** (for example ComfyUI or hermes-agent) carry a documented set of
  changes on top of their upstream. Fixes that belong upstream are better sent there.
- **Security issues** go through private reporting, never a public issue or pull request.
  See [SECURITY.md](SECURITY.md).

By contributing, you agree that your contribution is licensed under the repository's license.
